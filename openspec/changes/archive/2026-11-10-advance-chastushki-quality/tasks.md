# Tasks

Проходить группы по очереди. После каждой группы записывать результат
и решение. Если условие входа не выполнено, закрывать условные пункты
записью причины и переходить к следующей группе.

## 1. Образцы и независимый контроль

- [x] 1.1 Собрать короткий список кандидатов с источником и статусом пригодности точного текста. Готово, когда для каждого кандидата можно сверить текст и разметку.
- [x] 1.2 Проверить формат, естественность, ритм, рифму и шутку. Зафиксировать 2–3 подтверждённых образца или решение остановиться из-за нехватки материала.
- [x] 1.3 Если образцы собраны, зафиксировать baseline, одну замену блока и две непересекающиеся группы по восемь тем. Проверить отсутствие точных и близких пересечений с примерами и настроечными темами. Записать критерии из design до вызовов модели.

Итог группы 1: условие 1.3 не выполнено. Из восьми пригодных текстов
не удалось собрать блок положительных образцов. Причины записаны в
[журнале качества](../../../docs/quality-roadmap.md#2026-11-10--отбор-положительных-образцов-для-openspec).
Группа 2 закрыта по условию входа. Без блока образцов A/B и внедрение
не проводились. Базовый блок сохраняется.

## 2. Условная проверка нового блока образцов

- [x] 2.1 Подготовить eval-only вариант. Проверить сравнением входов, что между ветками меняется только блок положительных образцов.
- [x] 2.2 Выполнить один пилот и записать слепой результат по пригодности, отдельно формат, тему, время и число вызовов. Сверить решение с порогом из design.
- [x] 2.3 При прохождении пилота выполнить один подтверждающий блок на других темах. Записать итог и причину принятия или остановки.
- [x] 2.4 При принятии синхронно обновить текст навыка, манифест и версию. Проверить загрузку навыка и затронутые eval-тесты. При отказе зафиксировать, почему сохранили базовый блок.

## 3. Остаток работ по ранжированию

- [x] 3.1 Проверить доступность сохранённых кандидатов и человеческих оценок для отдельной абляции компонентов. Зафиксировать достаточные данные или недостающее основание для каждого компонента.
- [x] 3.2 При наличии данных посчитать смены выбора и пригодность на тех же кандидатах. Раздельно отразить формальные провалы, пары двух проходов и пары, в которых годится хотя бы один ответ. Записать решение о каждом компоненте.
- [x] 3.3 Определить статус штрафа за выдуманные слова. Для продолжения нужен размеченный пример дефекта и контрпример допустимого слова. Без них оставить задачу отложенной с записанным условием возврата.

Итог группы 3 записан в [журнале качества](../../../docs/quality-roadmap.md).
Компоненты ранжировщика сохранены. Условие возврата к штрафу за
выдуманные слова — разметка точных слов в контексте с допустимыми
контрпримерами.

## 4. Локальные модели и решение об обучении

- [x] 4.1 Зафиксировать цель локального запуска и доступное окружение. Если цель актуальна, составить отдельный сопоставимый протокол с одинаковыми темами, настройками и учётом качества, времени и памяти. Иначе записать причину отсрочки.
- [x] 4.2 Проверить готовность данных к дообучению. Зафиксировать происхождение, подтверждённую пригодность и разделение тем обучения, настройки и контроля. Записать недостающее и решение о целесообразности. Фактическое обучение вынести в отдельное изменение при положительном решении.

Итог группы 4: сравнение локальных моделей и запуск дообучения отложены.
Причины и условия возврата записаны в
[журнале качества](../../../docs/quality-roadmap.md).

## Workflow follow-up

- При первом применении пройти группу 1 и показать, получился ли пригодный набор.
- Перенести решения по группам в журнал качества. Закрытые пилоты остаются историческими результатами, а отложенные работы сохраняют условие возврата.
