# Смена модели в Misterio

## Восстановить генерацию

1. Возьмите точный идентификатор модели, HTTP-статус и текст ошибки из журнала
   сервера или тела ответа провайдера. Для Ollama Cloud сверьте идентификатор
   с `GET /api/tags`. Если ошибка указывает на квоту, проверьте `GET /api/balance`
   и `GET /api/usage?range=7d&group_by=model`. [Каталог и вывод моделей из
   эксплуатации](https://docs.ollama.com/cloud) · [Баланс](https://docs.ollama.com/api/balance)
   · [Статистика](https://docs.ollama.com/api/cloud-usage)
2. В UI выберите заведомо рабочий профиль и нажмите **Переключить**. Для сбоя
   отдельной модели Ollama Cloud используйте `mimo`, если он отвечает с текущим
   ключом. При сбое всего облака используйте заранее скачанный и проверенный
   локальный профиль `qwen` или `gigachat`. Переключение на локальный профиль
   останавливает текущие локальные LLM-контейнеры перед запуском выбранного.
3. Отправьте из UI одну тестовую задачу с обычной темой и проверьте, что получили
   полный текст. Кнопка переключения облачного профиля меняет выбор в памяти
   процесса, а доступность проверяется при генерации. После перезапуска UI
   загрузит профиль по умолчанию. Автоматического переключения при ошибке
   генерации пока нет. [Как работает переключатель](architecture.md#llm-backends)

Для разового запуска CLI явно укажите профиль. Выбор в UI действует только
в процессе UI.

```powershell
uv run misterio run "про трактор" --skill chastushki --model mimo
```

Если нужен локальный профиль в CLI, сначала запустите его сервер из Git Bash
через `./mist qwen` или `./mist giga`. Эти команды дожидаются ответа от сервера.

## Проверить постоянную замену

1. Зарегистрируйте модель-кандидата отдельным ключом в
   [реестре профилей](../src/misterio/models.py). Укажите точный идентификатор
   для API, подпись UI, URL, формат API и требование ключа. Добавьте запись
   в [реестр конфигураций eval](../evals/chastushki_model_configurations.json).
   Храните ключ в `.env` и используйте его только с предназначенным для него
   облачным endpoint.
2. Сделайте один запуск через `misterio run --model` с новым ключом профиля
   и проверьте полный текст. HTTP 200 на коротком запросе подтверждает
   доступность модели. Для проверки качества выполните пробный model eval
   на пяти контрольных темах. Сохраните его отдельно от базового прогона.
3. Перед постоянным переключением сравните долю прошедших проверку ответов,
   ошибки запросов и время на одном и том же наборе тем с одинаковым числом
   повторов, версией навыка и параметрами генерации. Если прежняя модель снята,
   используйте сохранённый сопоставимый отчёт или текущий рабочий резерв.
   Проверьте тексты вручную вслепую по плану качества. Зафиксируйте результаты
   с точными идентификаторами моделей. [План качества](quality-roadmap.md)

Команды пробного прогона для PowerShell. Замените `candidate-profile` ключом
из реестра. Тест обращается к реальной модели и требует доступного endpoint.
Используйте новый каталог для каждого запуска, поскольку отчёт с тем же
именем перезаписывается.

```powershell
$env:MISTERIO_RUN_MODEL_EVALS = '1'
$env:MISTERIO_EVAL_CASE_LIMIT = '5'
$env:MISTERIO_EVAL_REPETITIONS = '1'
$env:MISTERIO_EVALS_DIR = "data/evals/model-switch-$([guid]::NewGuid())"
uv run pytest tests/test_model_evals.py::test_real_model_chastushki_report -q --model-profile=candidate-profile
Remove-Item Env:MISTERIO_RUN_MODEL_EVALS, Env:MISTERIO_EVAL_CASE_LIMIT, Env:MISTERIO_EVAL_REPETITIONS, Env:MISTERIO_EVALS_DIR
```

Отчёт сохраняется и при недостижении порога. Для итогового сравнения
задайте одинаковые параметры обеим моделям и уберите ограничение на пять тем.
Сохраняйте прежний model ID в исторических отчётах и в `source_model`
размеченных пар. Запись снятого профиля можно убрать из действующего
реестра вместе с соответствующей записью конфигурации eval.

## Закрепить выбор и подготовить откат

1. Обновите `DEFAULT_MODEL_KEY` в [models.py](../src/misterio/models.py).
   UI, CLI, `./mist run` и model eval используют это значение, если профиль
   не задан явно. Обновите описания профилей и ожидания тестов.
2. Прогоните проверки, перезапустите UI и выполните одну генерацию без
   ручного выбора модели. Аналогично проверьте CLI без `--model` и
   `./mist run` без явного профиля.
3. Если качество или доступность ухудшились, переключите UI на проверенный
   резерв, явно выберите его в CLI и закрепите его как default, если сервису
   нужен перезапуск. Если предыдущая модель снята, откат профиля означает
   переход на доступный резерв. Возвращать ID снятой модели в default нельзя.

```powershell
uv run pytest tests/test_models.py tests/test_llm.py tests/test_api.py tests/test_cli.py tests/test_evals.py -q
uv run ruff check .
uv run pytest -q
```

В инциденте 9 ноября 2026 года Ollama вернула `410 Gone` с указанием, что
`mistral-large-3:675b` снята. `mimo-v2.6-flash` отработала пробный прогон,
а короткий вызов `mistral-large-4` подтвердил доступ с тем же ключом.

Чтобы в дальнейшем сохранять аварийный выбор между перезапусками без правки
кода, можно добавить настройку стартового профиля, которую проверяет allowlist
и читают UI, CLI и `mist`. Эта возможность требует отдельного изменения
приложения и проверки поведения при неизвестном профиле.
